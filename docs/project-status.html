The problem this started from

Recap, for context on everything below

The selector always picked MiniSat. The teammate feedback was "sample size too small" — that wasn't it. Four separate bugs stacked on top of each other, each invisible on its own:

  1. The timer started before clause loading, not before solve() — so the "runtime" measured was mostly per-solver setup overhead, and MiniSat has the least of it.
  2. Labels were single-run rather than median-of-repeats, so noise could flip a winner.
  3. The corpus wasn't sampled at the 4.26 clause/variable ratio where solvers actually disagree — most formulas were trivial for everyone, giving no signal.
  4. The GNN was a homogeneous bipartite graph that collapsed literal polarity (x and ¬x mapped to the same node), which throws away the one thing a SAT formula's structure actually encodes.

Full plain-English writeup with diagrams: docs/what-went-wrong.html. Everything below is what closed the remaining gaps after that diagnosis.

The fixes — PRs #1, #2, #3

All closed, superseded by #4 below — kept here for the record and the diffs

#1 · fix/label-timing-and-dashboard-rewrite

Timing, labels, corpus, model, GNN

Fixed all four root-cause bugs above: perf_counter around solve() only; median-of-3 labels with a tie band (20 ms or 1.1×) and an informative flag (1.5× gap) for training rows; random 3-SAT resampled at the phase transition; classical models given scaling, class balance, cross-validated PAR-2 scoring, and calibration, plus a regret-regression model that can't collapse to one class. The GNN was rewritten from a homogeneous bipartite graph to the tripartite GraSS architecture — separate var/lit/clause nodes across 4 relation types, literals keeping their polarity.

#2 · feat/satlib-full-coverage

Real benchmark data, not just generators

The download host (www.satlib.org) has been a parked domain for years — every prior build was 100% synthetic. Repointed to the canonical UBC mirror and fixed a DIMACS parser bug that rejected every real SATLIB file (they end in a % terminator line the parser didn't handle). Wired up all 15 archives — 2,210 real instances, weighted 5:1 by difficulty via largest-remainder apportionment, SAT/UNSAT kept at exact parity. New satsel sources command for cache/reachability status.

#3 · feat/probe-inprocess-and-feature-free

Feature-extraction budget, and objective O6

The feature probe spawned a subprocess per formula — ~0.45 s of interpreter startup, which blew the 5% extraction budget on anything but the slowest formulas. Rewritten to run in-process, stopped via the solver's own interrupt(): 156 ms at the default budget, inside budget at every setting from 20 ms to 1 s tested. Added search-space features (conflicts/decisions/propagations/restarts) that only exist because the probe is now in-process. Added the O6 feature-free ablation: cnf_to_hetero gains a node_feats mode (full / structural / none), train-gnn trains all modes on identical splits and reports the gap.

Why these are closed, not merged

All three were stacked (#2 on #1, #3 on #2). While waiting on review, vee1e opened #4, which folds the same backend work into one PR without the frontend rewrite that had bloated #1's diff with an 8k-line lockfile. #1–#3 were closed in favour of it. Their branches and diffs are unchanged and still on GitHub if anything here needs to be cross-checked against the original commit.

PR #4 — the consolidation

Open, mergeable, base main ← feat/consolidated-ml-pipeline

Two commits. The first folds #1–#3's backend work into one diff against main, deliberately excluding the frontend rewrite. The second is vee1e's own review pass over that consolidated diff — six real bugs and hardening items that weren't caught in #1–#3, on top of everything above.

Commit 2 · adversarial review findings

Six fixes found reviewing the consolidated diff

  • Crash-as-solved bug in labels.py — a solver that crashed twice and solved once could still win the median-of-3 label. Crash/error runs now count as not-finished.
  • Seed was silently dropped — pysat rejects a seed kwarg on every backend, so "independent repeats" were bit-identical runs. Now seeded via set_phases, so repeats actually search differently.
  • Probe wall clock still started after clause loading — the exact shape of bug 1 above, recurring in the new in-process probe from #3. Fixed by starting the clock at bootstrap_with.
  • Failed probe used to write fake zeros into training data instead of marking the feature group missing — silently corrupting rows rather than dropping them.
  • Download redirect handling — requests' automatic redirect following could silently downgrade an https→http 302, defeating the https-only check on the original URL. Redirects are now followed manually with a scheme check at each hop.
  • Allocator tie-break — leftover quota units from Hare-quota rounding used to always favour whichever archive came first, which was quietly biased toward the SAT half. Now goes to whichever tied archive least disturbs the SAT/UNSAT balance, verified across want=1..399.

Also: web_server.py got MAX_CONTENT_LENGTH so oversized request bodies are rejected before Flask buffers them, and /api/solve's timeout parameter now rejects negative/NaN values. Config drift was cleaned up (tie_margin aligned to 1.1, structural added to the ablation list since the docs already promised it, two dead config keys removed).

Net assessment

This is a real, independent review pass, not a rubber stamp — the seed bug and the probe-timing recurrence in particular are exactly the class of bug that's easy to reintroduce when consolidating three branches by hand. Verified: ruff clean, 64 passed / 1 skipped (the skip is test_gnn.py's 21 cases, skipped because the gnn extra — torch/torch-geometric — isn't installed in that environment; 64 + skipped-but-collectible ≈ the 85 known from #3). GitHub reports the PR as mergeable against current main.

The frontend question, settled

What "frontend is out" in the PR description actually means

PR #4's description says "Frontend is out… This PR has 0 files under frontend." That's true of the diff — the PR never touches anything under frontend/. It does not mean the directory is deleted. It's inherited unchanged from main, which has had a basic frontend since commit 0cd3368.

What actually settles it

PR #4's second commit doesn't just leave web_server.py alone — it rewrites 513 lines of it: request-size limits, input validation on /api/solve, an argument allowlist for the subprocess calls that launch pipeline steps, config-driven CORS. That's hardening work on a server that exists specifically to serve frontend/dist. Nobody is planning to delete the frontend — it's being kept and made safer to expose.

Net: the earlier plan to strip frontend/ and web_server.py down to a CLI-only repo is superseded. Nothing further needs to be pushed — the three branches that did that removal (still sitting on #1–#3, since those PRs are closed) can stay as-is and don't need to land anywhere. If the lockfile-size complaint that started that thread comes up again, the actual fix already happened: #4 never re-adds the duplicate package-lock.json that caused it, and the original bun.lock is the only lockfile in the tree.
